# UI/UX仕様・本番品質見本の条件 R2

## 0. 本資料とHTMLの役割
HTMLは「帰還・装備・探索・結果」の4画面、比較ダイアログ、構成の適用・解除、ボス選択を試す操作プレビュー。固定データを切り替えるだけで、実時間進行・戦闘アニメ・保存・IAPはない。
画面ごとのサンプルは独立。帰還の8hデータを、装備画面の毒装備と一つの実プレイ履歴に見せない。
最終アートの承認をHTMLの操作確認で代用しない。

## 1. 情報の優先順位
一画面の主操作は一つに絞る。「素材回収」「動画」「ショップ」「イベント」「ログイン特典」のボタンを同時に並べない。
G1の下部ナビは帰還・装備・探索・結果の4つ。製品版では結果は履歴と統合する可能性があるが、G1では比較しやすさを優先。

画面の表示と状態変更を分離。戻るだけで受取や広告視聴を再実行しない。

## 3. 帰還の表示
報酬は保存成功してから「成果は保存済み」と表示する。取得演出はまとめてスキップ可能。
注目候補は最大3点。判断理由は「初入手」「現在と異なる効果」等を示す。「最強」「絶対おすすめ」は表示しない。
0件なら、次の15分工程までの残りと現在の探索先を示す。時間操作で本番時間に見せない。
24h上限に達したら、実経過と有効時間の違いを説明。失った報酬の恐怖を煽るカウントダウンは付けない。

## 4. 装備の表示
総合戦力の単一スコアを主見出しにしない。攻撃・防御・ガード等の重要な数値を先に、詳細を一段下に。
装備の説明例：「通常攻撃で毒を1層。最大6層。1層につき毎秒20ダメージ。防御を無視」。20は構成全体であるなら「装備単体の効果」と混同せず明記する。
比較では低下を隠さない。例の変更は攻撃88→80、防御65→140、ガード5→23%、毒20→18、攻撃間隔0.746→0.819秒。
保存構成は3枠無料。名称変更、適用、上書きの確認。欠損アイテムは無言で他装備に置き換えず、欠損一覧を示す。

一括選別は対象件数・保護で除外する件数・得る素材のプレビューを出す。最終確認でロック状態を再検証する。

## 5. 戦闘の読み取り
攻撃は通常・会心・毒・反撃で視覚・文字表現を分ける。色だけでは識別しない。
会心や反撃のたびに長い演出で戦闘を止めない。早送りで計算を省略しない。
結果の助言は実測ログに基づく。「毒が最大層になる前に倒れた」「連撃に対しガード成功が少ない」等。勝利を確約する推薦にしない。
プレイヤーが見ていないことを「ユーザーが理解した」と記録しない。

## 6. タッチ・文字・アクセシビリティ
AppleのUI指針は少なくとも44×44ptの操作領域を案内する。本仕様の主ボタンは48ptを基本にし、密集させない。
本文は原則16pt前後を基準とし、重要数値は18〜24pt、補足の極小文字で仕様を説明しない。文字拡大で操作が消えないことを検証。
https://developer.apple.com/design/tips/

iPhoneの小画面確認は375×667と390×844相当の論理サイズを基準候補とする。これはサポートOS・端末の確約ではない。Safe Areaは実機の実値を使う。
横スクロールなし。下部の主操作がキーボードやHome Indicatorに隠れない。装備効果は省略したら全文への操作を用意する。
Reduce Motion、色に依存しない区別、スクリーンリーダー用ラベル、ダイアログのフォーカス移動・復帰を受入項目にする。
Web版のCSSpxをそのままiOSの物理ピクセルだと説明しない。

## 7. 本番品質見本 G2
代表の装備比較1画面と、それに続く短い戦闘・獲得演出を作る。最初から全地域の絵を量産しない。

### 必要な素材群
探索者1体、代表ボス1体、背景1枚、装備アイコン6点以上、通常／毒／ガード／反撃の短いエフェクト、取得・決定・ガードの効果音。権利・入手元・加工可否を記録する。
仮素材を本番品質と呼ばない。競合スクリーンショットや他作品の絵を制作素材に使わない。

### 評価項目
- キャラ・背景・アイコン・UIが同じ美術方向を向いているか。
- 通常文字の可読性と、戦闘の主役の視認性が両立しているか。
- 会心・毒・ガード・反撃が見て区別でき、効果説明と一致するか。
- 端末を閉じる／復帰する動作、長い所持一覧でも待ちがないか。
- 画面揺れや点滅を切っても、必要情報が残るか。
- 実機の低速・省電力状態で性能を測定したか。

**美術・音・実機の判定は未実施。** 品質を落として発売する許可ではなく、品質を判断できる範囲を小さくする方針。
