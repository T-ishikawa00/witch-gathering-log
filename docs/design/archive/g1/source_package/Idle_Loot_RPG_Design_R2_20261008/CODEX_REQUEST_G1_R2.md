# Codex依頼文 — Idle Loot RPG G1 / R2

添付 `Idle_Loot_RPG_Design_R2_20261008.zip` を、この依頼の仕様と参照モデルとして使ってください。
今回はiPhone向けゲームの**コアを試すローカル試作**を作ります。完成版全実装、公開、広告・課金SDKの本統合ではありません。

## 目的
「アプリを閉じた間に装備が集まる→短時間で選別・変更→ボス攻略が変わる」を、人が操作して判断できるようにする。
単なる静的画面や、ボスごとの勝敗をハードコードしたデモで終わらせない。
同梱HTMLは操作設計の固定サンプルであって、ゲームロジックの代用品ではない。

## 最初に読む順序
README → 01_DECISION_AND_GAME_DESIGN_R2 → spec/02〜05 → data/content.json → validation/core.py / progression.py / golden_fights.json。
報告する版は常に作業中の正確なsourceと結びつける。別の時点のテスト成功を流用しない。

## 作業前の安全確認
現在の作業フォルダ、既存AGENTS、Git状態、ディスク空き容量、利用可能なNode/TypeScript・テスト環境をread-onlyで確認。
このプロジェクトの作業フォルダが指定されているならそこを使用。未指定なら、現在の書込み可能な作業領域に衝突しない `idle-loot-rpg-g1` 子フォルダを作る。Windowsのパス・リポジトリ名を推測して既存作品へ上書きしない。
既存の変更、データ、未追跡ファイル、キャッシュ、他プロセスを削除・巻戻ししない。容量不足なら勝手に掃除せず、できる範囲と必要容量を記録する。

外部へのメール・DM・フォーム・投稿・招待は禁止。支払い、契約、アカウント作成、広告キャンペーン、TestFlight/App Store公開、外部公開URL作成、Git commit/push/deployは今回の許可に含めない。
依存導入は既存ルールに従い最小限。未許可の外部通信や大きなエンジン導入が必要なら実行せず、標準機能で進められる範囲を先に完成させる。テストサーバーは127.0.0.1限定、LANや公開トンネルに出さない。

## 技術の範囲
エンジン非依存の純粋な戦闘・進行コアを先に作る。G1は利用可能なTypeScript/JavaScript環境＋ローカルブラウザUIを第一案とする。これはApp StoreをやめてWeb事業に戻る判断ではなく、操作検証を軽量にするため。
Pythonは計算の参照であり、本番アプリにPythonを組み込む必要はない。
コア / content / persistence / UI / platform adapterを分離し、iOS最終技術はG2で決定する。課金と広告はインターフェースの予約まで。秘密情報や本番キーは不要。

## 実装順序（途中の軽微な判断で停止しない）
1. 参照モデルのテストを再実行。入力・出力・JSONデータ版を把握。
2. 戦闘の移植。整数切捨て、32bit unsigned、同時刻順、死亡、毒期限を合わせる。ゴールデン28戦を一致させる。
3. 自由な6枠編集・3つの保存構成・比較・保護を実装。固定3プリセットの選択だけで終えない。
4. 3ボスと自動戦闘・速度表示・結果内訳を実装。同じ入力・seedで表示速度が結果を変えない。
5. 3地域の放置収集・端数・上限・制作・重複処理・保留を実装。再読込を挟んでも重複しない。
6. 保存の原子性、世代保持、読戻し、失敗時復旧を実装。初期化でエラーを隠さない。
7. 帰還→比較→変更→ボス→結果→探索先変更の一連を操作可能にする。
8. 境界テスト、狭い画面、コンソールエラー、外部通信の有無、現行sourceの回帰を確認する。

UIの現行仮テーマを本番アートと呼ばない。G1では配置・比較・体験を優先し、機能する仮素材を用いる。全キャラ・全背景・音源の量産はしない。

## 実装しないもの
PvP、ランキング、ギルド、チャット、取引、独自ログイン、オンラインDB、ガチャ、実課金、実広告、サブスク、覚醒ツリー、ランダム副効果、地域追加、強制全画面広告、商用リリース。
市場性が未検証だからと言って、別ゲームや別事業の市場調査へ勝手に移らない。

## 確認ポイント
- `validation/golden_fights.json` と一致。
- 低攻撃力の混成でも連撃ボスを突破できる。
- 3系統以外の自由な混成が可能。相手属性に応じた強制正解フラグなし。
- 画面更新や受取連打で報酬を増やさない。
- ロック・装備中・保存参照・最後の1点の保護。
- 倉庫満杯で黙って停止せず保留を表示。
- 時計異常・保存失敗・不足素材から戻れる。
- 「8時間送り」は明示したデバッグモード、実経過ログと区別。

## 自律範囲と停止点
G1内のデバッグ・軽微なUI修正・テスト修正は自律継続。各バグや比較完了ごとにHumanへ聞かない。
ただし、仕様数値をテストに合わせて黙って変更しない。計算移植の誤りなら直す。設計を変更する場合は理由・比較結果・新旧差分を別記し、参照版も整合させる。
初回作業30時間は再評価の上限案。完成時間を保証するものではない。実際に計測できる範囲で作業時間・容量増分を記録し、上限前に最小の判断可能ビルドを優先する。
G1のプレイ可能版と試験報告がそろった所で止め、G2の全美術・iOS統合に進まない。重大な非可逆操作が必要なら、その操作は行わず独立作業を完成させる。
