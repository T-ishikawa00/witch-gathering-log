# Idle Loot RPG — G1開始前の抜け漏れ監査・補足依頼 R3

作成日: 2026-10-08  
位置づけ: `Idle_Loot_RPG_Design_R2_20261008.zip` への **G1限定の追加指示と、G2/G3の計画上の抜け漏れ一覧**。既存R2の戦闘計算・コンテンツID・数値・保存要件を変更するものではない。  
優先順位: **G1の追加受入条件は本書を適用**。戦闘・経済の数値、同時刻順、エッジケースの規範は従来どおり `data/content.json` とR2の仕様・参照コードを正本とする。矛盾が出たら黙って数値を変更せず、影響を記録する。

## A. 今回Codexへ追加したいもの（G1だけ）

### A1. 初回から試作終了までの最小進行（必須）
- 新規セーブ開始時に、R2ゲーム概要で指定した会心系6点が一度だけ付与・装備される。リロードで再付与しない。
- まず「崩門の番人を倒す」目標を明示し、クリア後はR2で記述済みの毒／防御を含む試用装備へのアクセスを案内する。試用装備の付与は初回だけ。通常ドロップ・所持履歴と混同しない。
- 3ボスそれぞれについてクリア履歴を保存し、結果画面と探索画面から到達目標／現在の達成状況を確認できるようにする。G1では正式版の地域ロック・クエスト・物語・大量の固定報酬を追加しない。
- 3ボスすべてをクリアしたら「G1試作の確認範囲を完了」と表示する。ゲーム本編のエンディングだと誤認させず、引き続き装備変更と再戦ができる。
- この進行表示の追加によって、既存の戦闘式・ドロップ率・素材コスト・ゴールデン28戦を変更しない。

### A2. 自動化したエンドツーエンド受入シナリオ（必須）
以下を最新sourceの一連の操作テストとして用意し、実行可否・未実施を結果に残す。
1. 新規セーブ -> 初期6装備 -> 番人への初回挑戦 -> 勝利記録 -> 試用装備を使える状態 -> 装備変更 -> 別ボスとの比較結果を確認。
2. 地域選択 -> 開発用8時間送り（画面に明示） -> 装備・素材受取 -> リロード -> 同じ時間分が再付与されない。
3. ロック／装備中／保存構成参照中の装備が自動処理・手動一括処理で失われない。
4. 保存中断または保存失敗 -> 従来セーブから再開 -> 報酬が重複も消失もしない（環境で実証できない故障注入は未実施と報告）。
5. 敗北 -> 戦闘理由と効果内訳を確認 -> 装備変更 -> 再挑戦。結果が別の能力／構成によって変わる。
6. 同じ装備、同じseed、異なる表示速度なら結果は不変。

### A3. 最小の観察ログとプレイテスト準備（推奨、G1の範囲内）
- 個人識別情報を取らないローカルのセッション記録を残せるようにする（例: 初回起動、装備変更、ボス挑戦・勝敗、時間送り利用、再起動、取得・分解、保存失敗）。外部送信型Analyticsや識別SDKは入れない。
- テストで実時間とデバッグ時間送りを必ず区別する。デバッグ操作は製品版から除外する前提とする。
- 1名が初見で何に迷ったか、何を試したかを後から振り返れる操作記録・簡単な観察用チェックシートを納品する。ユーザーテスト実施済みと偽らない。

### A4. 開発範囲と安全策（必須）
- 数値モデル・アイテム・端末保存・UIを疎結合にし、最終iOS実装方式が変わっても仕様・テストケースを移植可能にする。ただしブラウザのUIがそのままネイティブiOSへ流用できるとは主張しない。
- 作業前に対象フォルダ、Git、ディスク空き容量を確認。容量逼迫を理由に既存作品・キャッシュ・ユーザーデータを削除しない。
- 既存R2の禁止事項を維持する。外部通信、Git push/commit、公開、TestFlight、本番アカウント・課金・広告の操作は行わない。
- G1作業30時間は「途中レビュー用の上限案」であり所要時間保証ではない。上限が見えてきたら、A1・A2と戦闘／保存のコア動作を優先し、装飾やオプション機能は縮小する。重大な変更・新たな費用は勝手に決めない。

### A5. G1終了判定（今回の実装をこれで区切る）
**技術**: ゴールデン28戦と最新参照が一致。ローカルの新規開始→比較→変更→再戦→放置報酬→保存の流れが成立。受取重複や保護対象の消失がない。重大な未解決保存欠陥がない。  
**UX**: 画面単体ではなくA2の一連の操作を完了できる。戦闘結果から「何が影響したか」が分かる。  
**人の評価**: Codexの自動試験とは独立。本人による試用と、可能なら外部のジャンル経験者への観察を次の判断材料とする。未実施なら `USER_TEST_NOT_RUN`。  
**非達成事項**: ランダム装備の楽しさ、何週間もの継続率、課金率、App Storeからの自然流入はG1では判定しない。

## B. 今回作らないもの（G1のスコープを守る）
レアリティ、ランダム副効果、覚醒・転生、複数主人公、完成アート大量制作、追加7体のボス、商用UI、iOS正式ビルド、広告SDK、StoreKit、本番購入、ネットワークPvP、ギルド、アカウント・クラウドセーブ、外部投稿、公式公開、各種ストア手続。**G1でないことは未決事項ではなく意図的な分離**。

## C. G2で決め・検証すること（製品の核心）
1. **戦利品の気持ちよさ**: 固定18点から、装備インスタンスID、レアリティ、ランダム副効果、固有効果へ拡張。重複品・フィルタ・倉庫・保護の設計を作り直す。
2. **育成とやり込み**: レベル、装備強化、覚醒分岐、クラフト、通貨の獲得と消費、高難度挑戦の意義。数値インフレだけでなくビルド選択で突破する体験を守る。
3. **経済・進行**: 初回10分、最初の24時間、7日程度の進行をモデル化。ドロップ率、確定入手経路、停滞時の対応、広告がない人とプレミアム購入者の進行を比較。
4. **iOSの技術検証**: 開発エンジンとレンダラー・保存方式を決め、小さくiPhone実機で起動・復帰・長時間放置・発熱／電池・動作を測る。G1のTS UIを無理に本番利用する必要はない。
5. **本番品質の縦切り**: 主人公1体、ボス1体、UIの1画面群、代表的な装備・背景・演出・効果音を本番に近い品質で仕上げ、美術統一・視認性・容量・制作負担を確認する。素材ライセンス台帳を用意する。
6. **長期保存設計**: セーブバージョン移行、装備インスタンス増加への対応、復旧、機種変更・再インストール時の進行データの扱い（バックアップするか、保証しないか）を決める。
7. **課金商品の価値**: 強制広告を初期OFFとする一方で、980円を「広告削除」と呼ぶのか「任意広告報酬の恒久スキップ」と呼ぶのかは未決。ユーザーに正確な権利・期限・回数を説明できる商品にする。広告視聴を嫌になるほど要求して商品価値を作らない。価格も仮説。
8. **プレイヤーによる検証**: 初見で理解する、再挑戦する、翌日戻る、装備厳選を自発的に楽しむかの小規模テスト。少人数テストから商業的購入率を推定しない。
9. **発売範囲を正式決定**: 「5地域・10ボス・60〜80種の基本装備・伝説級12種・4〜5ビルド・2〜4週間」という以前の数字は暫定の目標であり、現在のR2依頼には正式受入仕様として入っていない。製作費・品質・テスト結果に応じ確定／削減する。

**G2→G3進行条件**: (a) 実際の装備厳選が楽しい、(b) 対応可能なコンテンツ制作負荷に収まる、(c) iPhone実機で技術成立、(d) 装備・進行データの保存仕様が破綻しない、(e) 広告・課金に頼る以前に無料部分が遊べる。このいずれかが不成立なら全量制作しない。

## D. G3で必要な工程（「ゲームを完成」で省略しない）
1. **完成コンテンツ**: 確定した地域・ボス・装備・覚醒・高難度要素、正常な成長曲線と上限／エンディング・エンドゲームの定義。
2. **正式UI/UXとアセット制作**: 初回導線、装備比較、フィルタ、結果、設定、音声、言語、アクセシビリティ、実画面に基づくビジュアル品質と演出。
3. **iOS製品化**: 最低対応iOS・端末、セーブの復旧／移行、クラッシュ、負荷、容量、電池、通知の要否、デバッグ機能の除去。
4. **課金・広告を安全に統合**: StoreKitで購入権利・復元・返金時の状態を管理。AdMob報酬は完了コールバックで一度だけ付与し、広告未取得・拒否でも通常プレイ継続。テスト広告IDのみで検証してから本番構成へ切替。
5. **プライバシー／審査**: SDKの収集データを含む開示、プライバシーポリシー、必要な同意・追跡許可、年齢区分、素材の利用許諾・商標、ストア審査資料。
6. **ストア販売・発見設計**: ゲーム名・説明・キーワード・アイコン・スクリーンショット・プレビュー動画。App Store内検索・推薦から何人が来るかは保証されず、発売前に検証方法を定める。
7. **公開前QA**: 実機とTestFlightで新規開始から終盤まで、長期放置、購入・復元・返金、広告異常、保存移行、UI崩れ、クラッシュ・フレーム落ちを確認。課金テストは本番売上と区別。
8. **公開後30日以上の観測と意思決定**: ストア表示→DL→初回体験→再訪→購入のファネル、クラッシュ、広告実績、問合せを確認。アクセスがないからといって装備を大量追加しない。追加開発・継続・撤退の判断ゲートを設ける。

### 特に未解決の事業上の問題
- **集客は未検証**。App Storeに置いても自然流入人数の保証はない。検索語の実需要・競合との差別化・アイコン／スクリーンショット転換率が未確認。
- **利益は未検証**。980円の恒久商品が何件売れるか、任意動画広告がどれだけ表示されるか、課金後の継続率は不明。
- **運用コストは未確定**。広告SDK・App Store開発環境・美術素材・維持費・実機検証の時間と容量を含め、追加支出は所有者承認とする。

## E. 三段階と、横断する意思決定の関係
- **G1**: 戦闘・装備変更・放置を操作可能な試作で検証する。今回Codexに許可するのはここまで。
- **G2**: ランダム戦利品・育成／覚醒・長期進行・iPhone本番技術・代表アートを検証し、正式発売ボリュームを確定する。
- **G3**: 全体制作、iOS製品化、広告／IAP、テスト、ストア提出準備、リリース後のデータ分析まで。G3内部は本制作→公開前QA→公開・観測に分割して別途承認する。

**横断する判断条件**: 予算上限／既存資産保護／市場での発見経路／テスト結果／公開・支払い等の外部操作に対する明示的なHuman承認。企画・テスト・設計の中間判断は自律的に進めても、G1から勝手にG2/G3へ進まない。
