1. 作品の見え方

「森の奥の静かな暮らし」と「知らない素材を調べる魔法の冒険」が同じ絵になること。キャラクター詳細は高品質アニメ設定画、ゲーム表示は輪郭に精密なドット感を残した2Dアクターと奥行きある環境を目標とする。特定作品のマップ・UI・キャラを複製しない。

Dotsが試作した二平面cutout方式は保持する。cutoutは制作手法、ドット感は表示結果なので同義ではない。毎フレーム別の顔/形に変わるAI動画、輪郭だけ低解像度で内部が写真、全体の一律ピクセル化で劣化する処理は合格にしない。

2. 地域・素材・機能の色を分離

環境色、素材の固有色、戦闘効果色、レアリティ枠の4系統を分離する。琥珀色の樹脂は通常素材でも琥珀色。霧が紫だから全敵が毒属性、金色だから伝説級とはしない。意味は形・動き・ラベルでも判別できるようにする。

共通の物質は布、革、木、淡石、真鍮色の既成留め具、魔力を通す鉱石。月の弧と蔓は既存の人造品に、自然の生物には葉脈・膜・鱗の物性として控えめに現れる。すべての魔物に人工の魔法陣や宝石を貼らない。

3. シーンの共通文法

背景は far → back → playfield → actor_shadow → actors → actor_vfx → front → presentation_overlay → UI の責務で組む。UIは背景画像に描かない。水/霧はどこを通るかを明示し、手前霧が攻撃予告を隠す場合は抑制する。

人物/敵を背景に描かない。特に古樹・竜・炉守りの巨体は遠景物に見えてもアクター。ボスを消しても背景に同じ身体が残る二重表示は不可。

前景の枝/葉は左右・下端の額縁。プレイフィールドは4人の足元、影、対象、予告を読める中間密度。背景を美しくするために画面中心を小物で埋めない。背景に採取素材を配置する場合、採取前後で変わるノード小物は独立する。

デザインの一致、可動部の継ぎ目、実サイズ視認性、実装の正しさ、iPhone性能は別の欄で記録する。Humanが見た目を承認した後、より良い案を理由に延々と描き直さない。不具合と好みの差を分け、既存の承認を範囲付きで継承する。

制作方式はcutout_rigまたはframe_sequence。dotsの既存cutoutを候補として維持する。前者は透明パーツ＋階層/ピボット/タイムライン、後者は透明フレーム＋継続時間＋未trimキャンバス/オフセット。両方式とも映像だけの納品は禁止。

ゲーム側が行動開始、攻撃対象、命中、ダメージ、状態異常、勝敗、報酬を決める。素材側が定義するのはnormalized phaseと見せ方。

地域ごとに環境ENVと戦闘FXを別キット。毒/糸/反射/詠唱妨害/冷気/種の波は各地域の物性に合わせるが、対象と効果の意味は共通HUDへ渡す。

共通マーカーは線/弧/扇/複数対象リンク/面。これらはCodex側のUI/プログラム図形として実装する案で、Dotsの159美術パッケージへ重複して追加しない。地域キットは物性VFXを担当する。環境と色が似る場合は輪郭線と明暗を補助する。予告中に手前霧/雪/花粉を重ねない。全画面連続フラッシュや常時強ブラーは使わない。軽減表示でも対象と発生順を残す。

6. ファイル規約

<asset_id>__<variant>__r001.ext。IDの意味を変えない。更新はr002等へ追加、r001を上書きしない。ゲームで選ばれる版は別のaccepted manifestで明示する。

runtime PNGはsRGBを基準案、alpha_modeをstraightまたはpremultipliedで記録し、Codex側の取込仕様で一度だけ変換する。背景の白縁/黒縁は白・黒・灰・地域背景へ合成して確認する。アルファ方式の文字が正しいだけでは品質確認にならない。

frame_sequenceは同じoriginal_canvasとground anchorを保持。trimするならsource_size、source_offset、pivotを必ず記録。実装atlasは必要時だけ生成し、原フレームを残す。cutoutは隠れていた肩/脚の描き足し、前後関係、極端角度の継ぎ目を確認する。

7. ソースと権利記録
