# QA・バッチ制作・受入 R4

## 1. DotsとChatの並行作業
Dotsは既存のR01背景1点＋猪1体の制作を継続。本R4を受け取る前の成果を撤去しない。Chatは全地域の設計、IDのつながり、共通仕様を作る。両者を同期するのはR01の編集元/パーツ/構図/座標が分かったとき。

本書のP0寸法が既存パーツと合わなければ、まず表示側の非破壊マッピングで比較する。全素材を描き直してP0へ合わせることを先にしない。

## 2. 量産前の代表サンプル
1. R01背景1系統＋猪の既存cutout。素材と中立背景の重ね、4人を重ねたサイズ、影、端のにじみ。
2. 透明素材の代表はR02水鏡くらげ、硬質多関節はR03連槌兵、大型はR04山竜の一部シーン。最初は輪郭/rig計画まででよく全尺完成を先行しない。
3. 本番描画方式、座標/スケール、cutoutまたはフレーム出力を一つのprofile_idで記録。

2と3は必要な技術リスクだけを拾うもので、第1地域の承認済み動きをもう一度最初から審査する依頼ではない。実装可否と画風の一致を確認する。

## 3. 一括制作する場合の順序案
全地域の規格承認と追加制作依頼があった後に実施。背景→魔物→素材→合成を機械的に全量分業せず、地域別の中間照合を挟む。

|Wave|内容|受入証拠|
|---|---|---|
|0|既存R01の保全、納品形式と取込の契約確認|ソース/metadata/hash/読戻し|
|1|10背景キットの基礎構図＋10地点差分のplan|敵なし画像、中央床、4人＋敵の仮配置|
|2|30魔物の造形、rigファミリーごとの分割|素材部位・行動予告・元資料一致|
|3|50素材＋20採取小物＋29装備アイコン|素材から装備まで87接続を目視/ID照合|
|4|各地域の必要モーション・環境/戦闘VFX|等速/倍速/軽減表示の確認動画|
|5|地域ごとの統合チェックと引継ぎ|manifest、既知制約、Codex取込結果、実機記録|

これは制作日数を保証する工程表ではない。R01の実測作業時間・手直し率から見積りを作る。資料159単位と実ファイル数/パーツ数を混同しない。

## 4. 受入チェック
|種別|合格の内容|合格にできないもの|
|---|---|---|
|設定一致|名前/ID/部位/素材/形が正本と一致|ポスターに似ているだけ|
|背景|敵/UI/文字なし、地形差分が機能|中央にボスの身体が残る|
|透過|白/黒/灰/地域背景で縁の汚れなし|MP4だけ、市松模様焼込|
|アニメ|脚の接続、重心、足接地、予告と後隙|身体全体の揺れだけで全行動を代用|
|視認性|4人と対象・HP・予告が重なっても読める|全画面発光/雪/霧で隠す|
|データ|canonical_id/variant/revision/paths/hash|名前が一致しているだけ|
|性能|対象端末とビルド識別子付き実測|Mac上MP4やブラウザ表示のみ|
|進行|報酬表示が未解放素材を先取りしない|背景美術が新しい素材を勝手に追加|

構造検査は内容の存在と接続を確認するだけ。美しさ、人体/動物の正しさ、快適な30/60fps、売上は保証しない。

## 5. コスト/容量の扱い
全方向・全季節・全時間帯・全装備外観を足さない。下絵や画像を無期限生成して候補を増やさず、採用候補と却下理由を記録する。原画は保存、ランタイムは必要な地域単位で読込する方針をCodexへ渡す。大きな依存導入/追加契約/課金は別承認。

## 6. 端末チェックは後回しのまま量産しない
最終iOS描画方式は未決。Macでのlook承認とiPhone合格を分離。最低1シーンの足元・UI・光・透過・省電力表示をiPhone実機で見るまではruntime profileをFROZEN扱いしない。エラーがあれば全部を止めるのではなく、機種依存しない設定図/ID整理は継続可能。
