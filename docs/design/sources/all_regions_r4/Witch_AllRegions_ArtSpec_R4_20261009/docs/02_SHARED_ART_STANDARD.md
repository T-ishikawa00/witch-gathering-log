# 全5地域 共通美術規格 R4

## 1. 作品の見え方
「森の奥の静かな暮らし」と「知らない素材を調べる魔法の冒険」が同じ絵になること。キャラクター詳細は高品質アニメ設定画、ゲーム表示は輪郭に精密なドット感を残した2Dアクターと奥行きある環境を目標とする。特定作品のマップ・UI・キャラを複製しない。

Dotsが試作した二平面cutout方式は保持する。**cutoutは制作手法、ドット感は表示結果**なので同義ではない。毎フレーム別の顔/形に変わるAI動画、輪郭だけ低解像度で内部が写真、全体の一律ピクセル化で劣化する処理は合格にしない。

## 2. 地域・素材・機能の色を分離
環境色、素材の固有色、戦闘効果色、レアリティ枠の4系統を分離する。琥珀色の樹脂は通常素材でも琥珀色。霧が紫だから全敵が毒属性、金色だから伝説級とはしない。意味は形・動き・ラベルでも判別できるようにする。

共通の物質は布、革、木、淡石、真鍮色の既成留め具、魔力を通す鉱石。月の弧と蔓は既存の人造品に、自然の生物には葉脈・膜・鱗の物性として控えめに現れる。すべての魔物に人工の魔法陣や宝石を貼らない。

## 3. シーンの共通文法
背景は `far → back → playfield → actor_shadow → actors → actor_vfx → front → presentation_overlay → UI` の責務で組む。UIは背景画像に描かない。水/霧はどこを通るかを明示し、手前霧が攻撃予告を隠す場合は抑制する。

人物/敵を背景に描かない。特に古樹・竜・炉守りの巨体は遠景物に見えてもアクター。ボスを消しても背景に同じ身体が残る二重表示は不可。

前景の枝/葉は左右・下端の額縁。プレイフィールドは4人の足元、影、対象、予告を読める中間密度。背景を美しくするために画面中心を小物で埋めない。背景に採取素材を配置する場合、採取前後で変わるノード小物は独立する。

## 4. 仮の表示プロファイル P0（実機未検証）
制作の比較を可能にする仮規格であり、エンジンや最終解像度の確定ではない。

|対象|比較用の値|確定条件|
|---|---|---|
|シーンの論理キャンバス|384×512、比率3:4|iPhone縦UIに4人＋敵＋HUDが読めること|
|背景の制作マスター|1536×2048を開始案|1レイヤーの大きさを無制限に増やさない|
|背景の仮runtime候補|768×1024と1536×2048を比較|実機の画質/メモリ/フレーム記録で一方を採用|
|人型の基準H|帽子を除く体高64論理pxを開始案|帽子・髪・赤スカーフを同時画面で識別|
|素材/装備アイコン|256pxマスター、64/128px確認|小サイズで形を判別、文字とレア枠は別|
|モーション|秒数はデモ用、実戦はnormalized phase|4人用ロジックの時刻と同期|

この比率に既存R01素材を直ちに切り直さない。Dotsの現物のキャンバス・ピボットを測り、非破壊で比較する。巨大な背景を縮小しても主体が判別できない場合、解像度増加ではなく構図を修正する。

ゲーム画面の外側の安全領域/端末差はCodexのレイアウトで処理する。特定iPhone型番の固定ノッチ値や広告領域を原画に焼き込まない。

## 5. 構図契約（正規化座標・左上原点）
- 背景の常時保護床：x=0.08〜0.94、y=0.56〜0.90。
- パーティーは左側の奥行きある配置。例：魔女(0.17,0.66)、弟子(0.16,0.86)、鍛冶師(0.37,0.77)、黒猫(0.34,0.88)。座標は足元。4者は画面の収容力を測る代理配置であり、未加入の弟子や鍛冶師を序盤へ出す指定ではない。実際の出現は加入フラグに従う。
- 通常敵の足元は右側(0.76,0.76)を開始案。複数敵は敵数/ターゲット仕様が決まるまで量産配置を固定しない。
- 主ボスは右上へ大きく見せる。樹冠・竜の翼端の画面外は許容案だが、頭/出射口/攻撃予告部は切らない。
- 大型ボスの高さ比は地域仕様のH倍率。画面へ収めるためにキャラ4人を米粒にしない。

これは自由移動マップや手動回避を追加するものではない。床予告は自動戦闘の行動を理解する表示であり、「避ける操作」が必要だとは解釈しない。

## 6. 統一しつつ、同じ色替えにしない
二つの甲虫はrigを共有できるが、琥珀の丸殻と白い板甲殻を別輪郭にする。二つの作業人形は技術史を共通にし、除氷具と重心を変える。蜥蜴は霧ひれ/磁紋/大冠鱗を分ける。鳥とこうもりは羽毛/膜翼、白角獣と月鹿は一本角/枝角を分ける。

共通リグの利用は再描画量を減らす候補で、同じフレームを色替えして全敵へ流用する承認ではない。

## 7. 目標を分けて評価
デザインの一致、可動部の継ぎ目、実サイズ視認性、実装の正しさ、iPhone性能は別の欄で記録する。Humanが見た目を承認した後、より良い案を理由に延々と描き直さない。不具合と好みの差を分け、既存の承認を範囲付きで継承する。

仮メモリの目安：RGBA8の1536×2048一面は12MiB、768×1024一面は3MiB（幅×高さ×4bytes）。圧縮PNGのファイルサイズは展開時メモリではない。ミップ/atlas余白/重複/GPU実装の費用は別。全画面レイヤー数を足しただけで実機合格とはしない。
