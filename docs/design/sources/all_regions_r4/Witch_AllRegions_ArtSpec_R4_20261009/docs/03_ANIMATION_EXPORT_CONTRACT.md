# アニメーション・納品・Codex取込契約 R4

## 1. 作る段階と納品物を混同しない
`reference`（雰囲気/切り出し/MP4）→ `concept`（1対象の設計）→ `source`（編集可能な原画/パーツ/rig）→ `export`（実装候補）→ `integrated`（ゲーム取込）→ `device_verified`。

MP4は動きの説明用。動画が良く見えても透過PNG、rig、パーツやフレームが納品されたとは扱わない。透過の市松模様を焼き込んだPNGも不合格。

## 2. 背景キット
各地域で`FIELD`と`BOSS`の2系統、計10。FIELDは入口が基準、探索地点02/03は大きな地形・小物差分と合成レシピを各1、計10差分。20地点を単なる色替えにせず、反対に20枚を完全に独立制作しない。

1系統の必須：編集元、空の合成見本、far/back/playfield/front（無い層は理由付きで省略可）、レイヤー配置JSON、足元と予告の保護マスク、縮尺テスト画像。水面/灯/霧は独立層または独立描画の指定。

背景の`far`は不透明でもよい。`front`やactorは真のalphaが必要。レイヤーの抜きで本来隠れていた領域は描き足しを行う。前景を外すと透明な穴や複製木が出る状態は納品不可。レイヤー分離＝一枚絵を雑に分割、ではない。

## 3. 魔物キット
通常20、ボス10、計30。各1体に最低限 `idle / anticipate / execute / recover / hit / resolve` の6状態。別行動を持つボスのanticipate/executeは行動ごとに分ける。**6状態は6枚の絵という意味ではない**。

最初の向きは3/4左向き。多方向・背面・8方向移動を全30体へ自動追加しない。鏡像は非対称模様・脚前後・持物に影響するので勝手に確定しない。

制作方式は`cutout_rig`または`frame_sequence`。dotsの既存cutoutを候補として維持する。前者は透明パーツ＋階層/ピボット/タイムライン、後者は透明フレーム＋継続時間＋未trimキャンバス/オフセット。両方式とも映像だけの納品は禁止。

必要anchorはground/body_center/head/action_origin/material_reference/nameplate。material_referenceは設定図の対応点であり、戦闘後にそこから素材を射出する指示ではない。特に月鹿の種は種床、古樹の枝節は譲渡として別表示。

## 4. 動きとゲーム判定の所有権
ゲーム側が行動開始、攻撃対象、命中、ダメージ、状態異常、勝敗、報酬を決める。素材側が定義するのはnormalized phaseと見せ方。

`anticipation_start`→`cue_peak`→`impact_present`→`recover_end`を表示イベントとして使う。`impact_present`が再生された回数からダメージやドロップを計算しない。倍速、演出スキップ、フレーム落ち、スリープ復帰でも戦闘結果は同じ。

本体の前後移動はruntime rootの所有。描画側はin_placeの脚/頭の動きとanchored VFX。MP4の見せ場の移動をパーツ側とゲーム側で二重に足さない。

設定上に「反射」「三連打」があっても、バランス値・発動率は新4人戦闘仕様の責務。旧G1一致の28戦/69,984戦を新戦闘の合格証として使用しない。

## 5. VFX
地域ごとに環境ENVと戦闘FXを別キット。毒/糸/反射/詠唱妨害/冷気/種の波は各地域の物性に合わせるが、対象と効果の意味は共通HUDへ渡す。

共通マーカーは線/弧/扇/複数対象リンク/面。これらはCodex側のUI/プログラム図形として実装する案で、Dotsの159美術パッケージへ重複して追加しない。地域キットは物性VFXを担当する。環境と色が似る場合は輪郭線と明暗を補助する。予告中に手前霧/雪/花粉を重ねない。全画面連続フラッシュや常時強ブラーは使わない。軽減表示でも対象と発生順を残す。

## 6. ファイル規約
`<asset_id>__<variant>__r001.ext`。IDの意味を変えない。更新はr002等へ追加、r001を上書きしない。ゲームで選ばれる版は別のaccepted manifestで明示する。

runtime PNGはsRGBを基準案、alpha_modeを`straight`または`premultiplied`で記録し、Codex側の取込仕様で一度だけ変換する。背景の白縁/黒縁は白・黒・灰・地域背景へ合成して確認する。アルファ方式の文字が正しいだけでは品質確認にならない。

frame_sequenceは同じoriginal_canvasとground anchorを保持。trimするならsource_size、source_offset、pivotを必ず記録。実装atlasは必要時だけ生成し、原フレームを残す。cutoutは隠れていた肩/脚の描き足し、前後関係、極端角度の継ぎ目を確認する。

## 7. ソースと権利記録
使用ツール/モデル、生成日時、参照画像のhash、編集履歴、利用権の根拠、生成費用が発生したかを記録。未知はUNKNOWNとし、著作権処理済みと断言しない。ライセンス確認のために新しいサービスへ契約しない。

## 8. 具体的納品一覧
- metadata付きsource一式、個別export、確認用stillとMP4、hash一覧。
- `delivery_manifest.json`：profile_id、entity_id、canonical_id、原画/パーツ/フレーム、alpha、anchor、clip、既知問題、端末テスト状態。
- 既存R01のファイルは新規命名のために消したり移動しない。原名→stable asset_idのmappingを追加する。
- `templates/`のJSONは**空欄を埋めるための雛形**。未完成物を実在する納品として取り込まない。
