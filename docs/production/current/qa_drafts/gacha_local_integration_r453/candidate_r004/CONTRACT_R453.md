# R453 local receipt-delivery candidate

Status: `UNAPPROVED_TEST_OVERLAY`. This is a host-side fixture exporter over the existing Python `PurchaseAuthority`. It does not verify Apple signatures, start a server, wire StoreKit into the game, authorize production entitlement, choose formal prices/rates, or establish release readiness.

The event envelope is deliberately stricter than the current `StoreKitLocalQAEvent`: in addition to the Xcode environment, bundle, product, transaction ID, and event key, this local test envelope requires original transaction ID, quantity, app-account token, purchase timestamp, and an explicit test account ID. Those fields are needed to test the authority boundary; the current Swift event does not carry all of them, so this candidate does not claim a StoreKit-to-authority integration.

The ticket-grant operation commits through `purchase_and_draw_mock` with zero draws. A later draw is a separate `draw_mock` operation, constrained to the referenced, currently verified FIFO ticket lot. The R004 adapter passes the full expected source identity into `draw_mock`; that identity becomes part of the idempotency request only for callers that opt in, preserving historical fingerprints for unbound calls. Under the authority's existing `BEGIN IMMEDIATE`, the authority checks that the FIFO head is the expected `(environment, bundle, transaction)` and that this single lot has enough tickets before RNG or spend. This prevents a concurrent draw from causing this request to spill into a different ticket lot. The adapter verifies the saved `balance_draw` source rows before exporting gear and expects their purchase columns to be `NULL`, as required by the current schema. Refund or refund tombstone state blocks a new export and replay. Previously exported local gear is not automatically removed by the authority refund path; the revocation fixture says so explicitly and requires a later save reconciliation design.

The JSON fixture’s `gearInstances` array uses the current Core `GearInstance` field names directly: `id`, `definitionID`, `ownerID`, `protected`, `enhancement`, `refinement`, `latentEffectID`, `candidateLatentSlots`, `qualityID`, `affixIDs`, and `investmentDust`. Per-item provenance is kept in a separate `gearProvenance` array joined by `gearID`. `postPityState` uses the current four `GachaPityState` keys. Ticket currency remains in the authority ledger and is not folded into Core game currency. The operation UUID and profile fingerprint bind the payload; item UUIDs are UUIDv5 values derived from the fixed R453 namespace, profile fingerprint, test account, transaction, operation UUID, and draw ordinal.

Quality-to-affix/latent mapping is supplied by an explicitly pinned candidate profile. Affix and latent IDs must end in `_TEST`, affix count is capped at four, and caller-supplied gear payload fields are rejected. The example profile is built from the 33 gear IDs and slot/actor compatibility rows in the pinned current catalog; its quality overlays are test-only. The focused unit authority fixture intentionally uses only two of those existing gear IDs. Neither file adopts a draw rate or item policy. The authority continues to provide its existing seeded candidate draw; this adapter adds deterministic serialization and item identity, not a new or production RNG.

The adapter stores its delivery receipt in a separate local sidecar SQLite file so a crash after the authority commit can retry the same authority idempotency key and reconstruct the same item UUIDs. The two databases are not one transaction. The later Swift importer must use `SaveRepository.transact` with the receipt’s stable `operationID` and fingerprint so repeated import cannot add the same UUID twice. R004 makes the narrow optional authority change in `draw_mock`; it adds no database columns/tables and leaves unbound legacy request fingerprints unchanged. No change to SaveRepository, Core, App, StoreKit, or `ingest_apple_jws()` is part of this candidate.

The test module covers ticket-only grant then a separate draw, exact replay with the same count and seed, same-operation count collision, profile-payload collision, sidecar-write failure recovery, current refund and pre-purchase tombstone suppression, stable distinct item UUIDs, strict identity/schema/template checks, full FIFO transaction tuple checks, hardlink rejection, pre-mutation CLI output collision, the still-fail-closed Apple JWS entrypoint, atomic source-lot rejection under an interleaved draw, and unchanged replay semantics for legacy unbound calls. Tests and CLI were not run by this candidate author. A Python syntax compile check was inadvertently run once during authoring; no test database was opened and no test ran.

The exported JSON uses the concrete keys shown in `EVENT_ENVELOPE_EXAMPLE_R453.json` and `PROFILE_EXAMPLE_R453.json`. A gear receipt contains `schemaVersion`, `status`, `candidateRulesID`, `profileID`, `profileFingerprint`, `operationID`, `receiptFingerprint`, `transaction`, `drawReceipt`, `gearInstances`, `gearProvenance`, `postPityState`, and `productionEntitlementAuthorized`. Ticket-grant and revocation receipts carry their own status and details. The receipt does not contain generic `accountID`, `source`, `rulesStatus`, `testOnly`, or `ticketCurrency` fields; ticket state remains in the authority ledger.

The CLI requires `--allow-test-mock-verifier`, a profile JSON and exact file-byte SHA-256, a mock event JSON, an already existing isolated authority test database, a separate delivery-cache database path, and a new output JSON path whose parent already exists. Symlinked path components, hardlinked authority/cache aliases, input/output aliases, and output paths that already exist are rejected before `PurchaseAuthority` initialization or authority/cache mutation. It has no network/listener mode and refuses to overwrite output. Passing an Apple-looking marker does not create Apple verification.

## Remaining integration gates

- The Swift importer must decode the exact `GearInstance`/pity keys, verify fixture and receipt hashes, confirm current transaction state, and apply gear plus stable operation receipt in one `SaveRepository.transact` call.
- StoreKit's current event schema does not provide all required authority identity fields; a reviewed local-only test envelope or a later authenticated backend contract is still needed.
- Revoking after a successful Swift import does not retract already imported gear. Reconciliation behavior is intentionally not invented here.
- `PurchaseAuthority.ingest_apple_jws()` remains unavailable and fail-closed. No Sandbox, device, production entitlement, external credential, or paid transaction was used or verified.
