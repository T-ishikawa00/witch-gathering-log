# ③〜⑤の受入基準と完了/停止の区別

## ③ 装備・収集・経済・収益化の統合仕様
- 実装可能な統合データschema、安定ID、設定/バージョン管理。4人完全自動を維持。29+猫4型、`AF_BARRIER`/`AF_WARD`、進化先潜在効果を合理的に解決し、検証可能な契約テストあり。
- LRの価値を単なる強さ倍率だけでなく、型固有効果、外見、ビルド、攻略目標へ接続。
- 少なくとも毒/結界/反撃/回復/追撃などの複数構成、15研究課題の敵条件を仕様化。直接攻撃型が常に唯一正解でないことを、実装した固有効果と対象戦況で検証する。勝率・時間・安全性・必要資源・解法複数性を証跡化。差が出ない場合は設計に戻して改善。
- ガチャの正確な確率・保証・目標選択・重複・潜在枠・分解保護・無料配布・ログ/復帰契約を定義。
- 無課金、広告視聴なし、少額単発、広告省略のみ、外観のみ、小包、継続少額、高額収集の各条件で、30/90日を比較。装備箱・余剰資源・導線・完全性を検証。シミュレーションの後半を勝利仮定にした場合は「攻略検証済み」と記載しない。
- 販売/法律/アカウントの検証課題をリリースブロッカーへ分離。人間による楽しさ/購入価値判断を数式から自動承認しない。

## ④ UI・アート・制作規格
- A案の美術方針を保つ。ホーム/探索/仲間/工房/採集帳と、魔導庫、試着、模様替え、商店、報酬、保存/確認、設定、エラー状態をiPhone実画面として実装・評価。
- ゲーム内実際の操作画面の証拠を提出。レポート用HTMLや1枚のコンセプト画像だけを「UI完成」としない。
- キャラクター正本維持。衣装/武器/家具が、所持権/装備性能/選択外見/配置と独立し、家/仲間/戦闘に反映される試作を成立させる。例えばエルナ1追加衣装×杖2外観×家/戦闘/詳細、机または椅子1カテゴリ×仲間の利用動作を先に成立。
- 将来拡張可能なレイヤー・前後関係・マスク・anchor・動作規格、権利/アセットidを定義。既存キャラを塗りつぶす、背景に家具を焼き込んで後から差し替え不能、膨大な衣装全組合せの無断量産をしない。
- iPhone小画面/大画面、safe area、文字の判読、タップ誤操作、広告/ショップの押し間違い、メモリと描画負荷を評価。

## ⑤ iOSアプリ統合・品質監査
- 原G1（1人ブラウザ試作）は保存。既存G2 SpriteKit/制作物を監査し、生かせるものを流用。勝手に古い成果を消して全面作り直しにしない。
- 四人完全自動戦闘と状態遷移/報酬、5地域の探索・素材・制作・進化・強化・研成・品質昇格・ガチャ/抽選後整理・保存をつなぐ。途中は仮アセット可、最終評価では仮物が残った箇所を未完成として数える。
- 装備ID/レアリティ/副効果/戦闘イベント/報酬を同じ参照契約に統合。戦闘表示デモfixtureを「R6実統合」と誤記しない。
- 無課金/報酬広告/広告省略/外見購入/有料券は、購入台帳/乱数結果/保証/復元/返金/重複実行/時刻改ざん/複数端末などの整合性を設計・試験。実課金ができない場合はStoreKit Test / Sandbox / mockで検証し、本番課金経路は未検証扱い。有料抽選はクライアントだけで結果を信頼しない。購入券と永続的な装備履歴・サーバー権威を接続する設計が必要。
- 単体・契約・回帰・統合・バランス・UI・性能・ライフサイクル・セキュリティQA。全地域の実際の戦闘敵行動を検証できない限り「全地域の戦闘QA済」としない。
- iOS Simulatorで実buildを起動しスクリーンショット/ログと再現手順。物理iPhoneは機器が見つかり、実際に計測した場合のみPASS。無ければ保留。

## 自律性とHuman Gate
- 設計上の小さな問題、候補不採用、試験失敗では止まらず、独立監査を含めて自律反復。
- ゲームの基礎方針、人物外観、A美術方向は変えない。根幹の大幅変更案は別の候補として保存し、既存と比較できるようにする。
- 未承認の候補値は「比較/実装試験の暫定設定」として試せるが、正式承認済みとして台帳へ記載しない。Humanの最終美術採用、課金商品の正式販売判断、App Storeの提出は依然別。
- 支払い、契約、実ユーザー/企業への外部連絡、公開/配信、ライブIAP、GitHubへのpushなどは許可なしに行わない。
- Apple Developerの認証情報、秘密鍵、決済設定、サーバーアカウント、外部SDKの有料費用、物理実機などにアクセスできない場合は、独立して進められる作業を先に完了。ブロッカーを詳しく報告し、虚偽の完了を宣言しない。

## 報告書の最終形
1. CURRENT_STATUS：③④⑤の各工程のDONE/PARTIAL/BLOCKEDと具体的証拠。
2. DECISIONS：Human確定/比較候補/廃案/未解決。
3. CONTENT：4人×5地域×装備×研究課題×衣装・家具の実装・QA台帳。
4. QUALITY：テストコマンド/件数/再現可能な乱数/失敗/未実施と性能・UI動画。
5. ECONOMY：30/90日、支出別、長期ビルド比較。仮定と実戦闘の区別。
6. GATES：Humanが承認すべき最小の重要判断、購入/公開に必要な別承認。
7. NEXT_ACTION：残りがあれば優先順位・見積りではなく具体的ファイルと欠落条件。
