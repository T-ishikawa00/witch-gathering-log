2. 装備ガチャの商品設計

2.1 商品が生む価値

魔導庫（仮称）で、各地の旧工房に残る道具を鑑定・取り寄せる。生き物から衣服が直接出る物語には変えない。

  • 自然探索：広く装備や素材に出会う。採集で強化・研究・進化を進める。
  • 工房：材料を払えば目的の型に届く。進化型の初回解放を担う。
  • 魔導庫：選んだ型への集中、希少以上、用途に合う副効果、良い個体値の範囲を提供する。

有料限定の上位能力上限や、同名品を大量に重ねないと主能力を使えない仕様は初期に入れない。最高品質を引いても、全員分の研成・強化・研究・覚醒まで完了しない。能力は同じ装備エンジンへ渡す。

これは購入需要を証明しない。無料探索でも最高品質が出る既存案なので、実際の格好よさ・副効果・狙いやすさに支払う価値があるかを試す必要がある。売れなければ、先に商品価値と価格を再評価し、無料報酬を黙って劣化させない。

2.2 排出候補の適格条件

pool = コンテンツ提供可能 ∩ 地域条件解放済み ∩ 加入キャラに装備可能 ∩ 進化型なら初回制作済み

魔導庫の解放案は G_R01_A + 4人加入 + 工房導入完了 + 適格型2種類以上。導入前に購入を促さない。最低1本の装備を自分で作り、装備比較が分かってから入口を開く。

全装備を同じ鍋へ入れて引かせるのではなく、利用可能な装備型から一つ「今回探す道具」を選ぶ。これは戦闘のAI設定ではない。初期選択は主人公の利用可能な杖。装備箱・工房から同じ型を指定して魔導庫へ移れる。

進化系の例：根守りの結界杖 EQ_W_G1 は G_R01_B を満たし、初回制作した後に候補になる。最高地域の装備が序盤に出たり、使えない当たりを長期間保管させたりしない。高位地域へ入っただけで未解放研成を与えず、サーバーが確認した研成上限を使用する。

購入前と抽選前に現在の排出リストを確認できる。無料・有料のどちらの券も同じリスト・確率・保証。衣装・家具・未加入キャラ用装備を装備ガチャの外れにしない。

2.4 品質・目標保証

全て希少以上。 普通・良質を有料対応抽選へ入れない。旧自然ドロップの品質率・保証には手を付けない。

三つのルールを一回ごとに順番に適用する。

1. 伝説が39回連続して出なかったら、次の40回目は伝説。 伝説が出たらこのカウンターを0へ。

2. 特級以上が9回連続して出なかったら、次の10回目は特級以上。 この回も伝説確率は通常3%、伝説天井到達時は100%。特級だけに置換して伝説を消さない。

3. 対象の型が出る通常確率は各品質で50%。伝説で対象外だったら、次の伝説は選択中の型。 その他の型は残り50%を適格な非対象型で均等配分。型が増えても目標50%は低下しない。

強い保証を優先し、1回で2個に増やさない。特級以上の10回保証は10連だけの特典ではなく単発でも共通。最高品質保証と目標保証を混同しない。

目標伝説を引くと対象保証フラグを解除する。目標を変更しても最高品質カウンター・特級カウンター・次回対象確定フラグは保持する。新しい対象が適格かを確認する。対象を替えた履歴から確率を個別操作しない。

初期状態から、同じ目標を選び続けたとき、最悪でも80回で目標伝説。 任意時点の上限は、次回対象確定なら 40−伝説未出回数、それ以外なら 80−伝説未出回数。無料券も同じ進捗へ寄与する。期間でリセットしない。

カタログ更新は同じ保証系列を維持する。直前の排出リスト・アカウント版・確率版を確認したquoteを使用し、内容が変わったら未消費で確認へ戻す。通信断の再送では、結果保存済みなら古いquoteでも同じ結果を返す。

2.5 伝説が当たった後の価値

最初の副効果は型の用途に沿う1枠を固定保証する案。例：毒杖は呪毒、結界杖は結界、弟子の本は回復、初期の共用護符はHP。残りを適格候補から重複なしで抽選する。型ごとの新しい対応表はデータ同梱。旧R2の正式副効果表を取得したときに照合する。

各数値は、同じ品質・研成で既存ゲームが許可する副効果範囲の上半分から抽選する案。例として元範囲4〜8なら6〜8。元の最高値は上げない。旧R2のQ4最小値が既に高い場合も、その合法範囲内の上半分とする。生の個体値座標を固定500に上書きする意味ではない。

保証するのは用途と下限であり、現在装備より必ず強いことではない。能力上限に達している、別ビルドで使わない場合もあるため、有効値と増分を購入/結果/比較で混同しない。

研成は現時点で合法な上限をnative rankとして持つ。強化値は+0。取得時に実際に払った強化投資は0。分解で未払い投資を返さない。既存の自然/制作個体も同じ最高能力へ到達可能な経路を残す。

2.6 見た目と重複

型の造形が主役。伝説は金属細工・魔導光・開封時の描写を強めるが、戦闘中に巨大発光や画面遮蔽を増やさない。品質別の装飾は共通部品やパラメータで支え、品質が上がるたびに別キャラの全身を描き直さない。

初回取得時は大きな道具表示、造形の細部、何が得意か、誰に持たせられるかを見せる。演出を飛ばしても結果を失わず、10回結果は一覧から個別比較へ。完成アートの試着確認前に価値があると断定しない。

重複は別個体として保持。自動凸・自動消費はしない。伝説は初期ロック、同型の最良個体/装備中/保存セット参照を保護する。分解は実投資と既存の返却式を確認。所持上限時は削除せず、課金由来も結果受信箱へ安全に保存。追加枠課金を結果受取りの条件にしない。

特定の異種ガチャ装備を集めると新能力や報酬を与えるセット収集は初期に採らない。役割・状態に基づく通常の連携と、特定商品を揃える報酬は別に審査する。

3%・40回の伝説保証では、伝説までの平均は約23.476回。対象50%と次回対象確定を合わせると、目標伝説までの平均は約35.214回、中央値38回、95%点78回、上限80回。基礎3%と保証込みの長期伝説率約4.260%を区別する。

5万の独立した目標到達系列で有限状態の確率計算を照合。乱数は検証用。結果は ANALYSIS_RESULTS_R2.json。目標が出る確率は型数2/8/16/29で50%のままという規則も確認した。

4. 恒常効果：暮らし共鳴（仮称）

4.1 具体的な候補値

取得元候補の記録値
各地域主ボス初回の暮らし研究20ずつ、5地域で100
追加衣装の初回所有20/衣装
追加家具の初回所有2/家具
標準衣装・基本家具、同一品の重複追加0

共鳴点 = min(100, 地域進行で得た点 + 現在有効な所有品の点)

暮らし補正 = 共鳴点 × 3 basis points

最大300bp、すなわちHP・威力・防護それぞれ既存の加算百分率へ最大+3ポイント。独立の乗算枠は作らない。衣装と家具でも別枠にしない。既存の能力上限が先に効けば実増分は小さくなる/0になる。

例：HP基礎100、既存の同群+50%なら、上限未到達で150→153。150×1.03=154.5ではない。ゲーム本体の固定小数点に接続するときは、R6の同群補正と上限の位置を必ず確認する。

速度、クールダウン、ドロップ率、ガチャ確率、スキル解放、行動権には効果を付けない。HP・攻撃・防御が全て増えるので、総合有利さが3%以内になるとは言わない。

4.2 自由な着せ替えと無料経路

所持で有効になり、着用・配置は条件にしない。古い好きな衣装や、部屋に似合う家具へ戻しても弱くならない。販売品をさらに追加しても共鳴上限100は増やさない。

通常プレイでも、各地域の主ボス初回で20ずつ、全5地域で同じ上限に達する。新しい繰り返し日課や時限通貨にはしない。ボス勝利時に一度記録し、そのボスの初回攻略へ遡って能力を加えない。

例：森攻略20＋追加衣装1着20＋家具5点10 = 50点、各能力の同群+1.5ポイント。全5地域攻略後は既に100点なので、新衣装を買っても能力増分0。購入前にその事実を表示する。

「無料で同じ上限へ届く」はこの構造上の経路であり、所要日数・無課金勝率を検証した意味ではない。難易度は当該ボスより前の無料点を基準に調整し、衣装購入を攻略前提にしない。

4.3 未解決リスク

R6で残った「HPが増えると支援判断が変わる」問題がある。共鳴0/150/300bp、攻撃/防御/回復構成、装備上限付近で同seedの再試験が必要。今回の模擬上限テストはR6の勝率や単調性の証明ではない。

衣装を追加するたびに戦力が無限上昇しないことと、全ての戦闘で損をしないことは別。悪化例を隠さず保存する。発売前にR6へ接続して検証できなければ、効果を売り文句として販売開始しない。

5.2 能力と見た目の分離

equipment_instance（性能）/ content_entitlement（所持権）/ appearance_selection（選択外見）/ furniture_layout（配置）/ living_progress（効果）を分ける。

衣装は全身セットで、帽子/袖/靴の自由な混用を初期から全保証しない。戦闘用防具を替えても、選択衣装は維持。武器は装備中の型を基本の外観へ反映し、初期には独立した武器見た目販売を追加しない。

武器の見た目や品質が変わっても、攻撃回数・ヒット時刻・射程・対象選択は戦闘計算に従う。衣装の大きさはゲームの当たり判定を変更しない。

6.2 共通アンカーと分離

キャラごとに足元、前後の手、握り、エフェクト起点を版管理する。杖の先端、槌の接触点、本の頁/魔法の発射位置、猫の爪触媒はカテゴリ別に定義し、全武器を同じ一本棒のリグへ無理に載せない。

衣装が変わってもキャラの同一性・体格・足元基準を維持する。裾や帽子に必要な隠れた面を描く。関節を動かしたときの穴を拡大縮小だけで隠し続けない。

家では常に武器を握らせる必要はない。本を読む/調合する間は作業用の小物を使い、装備武器は対応する傍の表示へ置くなど、動作に自然な規則を使う。装備武器が消えたと誤解されるUIは避ける。

6.3 時刻と演出

プレゼンテーションは計算済みのactor/action/target/timeを受ける。ヒットは計算の時刻。演出を飛ばす、衣装差分でclipを変える、画面速度を上げることによって報酬・ダメージを変更しない。

今の20秒周期のデモは戦闘エンジンではない。R6正式イベント型未受領のままAPI互換と断定しない。初回は入力アダプタを試験用に分ける。

6.4 衣装品質の受入

白/黒/灰/ゲーム背景上の透過、握りと足元、両手と武器の重なり、24→追加全尺の遷移、被弾後の復帰、椅子や机との接触を、実表示サイズと拡大で確認する。最終的な造形はHumanが確認し、技術テスト通過だけで昇格しない。

同じ画風でも、対象の顔や衣装が別デザインへ変わる生成結果は不合格。軽微な問題と構造的な破綻を分け、代表で成立した方式を展開する。

7. 家具・家の制作規格

A案の固定カメラ・高品質な室内を維持し、固定カテゴリの配置スロットを使う。最初から自由回転・任意倍率・無限配置・多数の部屋は増やさない。

基本の部屋、空背景/underpaint、10カテゴリの基本家具、差し替え家具、人物、遮蔽、影、照明、HUDを分離する。机や椅子を外したとき、後ろの床・壁が欠損しないこと。

家具にはcategory、占有範囲、対応socket、座面/手の接点、前後マスク、shadow、使用可能な動作、UIを塞がない範囲を含める。机と椅子はペアの互換クラスで高さを固定し、どちらの見た目を替えても本を読む姿が破綻しない。

暖炉や窓は位置を変えず、外装を替える。家具1点の購入権は同じ部屋の対応スロットで1点使う。多室や重複配置を初期に売らない。模様替え案は確認後に反映し、未購入の試し置きを正式配置へ保存しない。

朝・夜の光は共通の照明層で調整し、全家具×全時刻の別原画を必須にしない。特定家具の所有で採集効率が変わる仕組みを加えない。

家の人物は「遠征隊の帰宅/休憩の情景」として見せ、遠征中に別の4人が家でも素材を生産する扱いにしない。家の着せ替えは次の場面切替で反映し、進行中の戦闘HPや過去の放置成果へ遡らない。

8. 先行の制作検証と量産数量

最初の実制作確認は、エルナの標準＋追加衣装1着、杖2外観、机＋椅子の差し替え。 最小パッケージであって商品総数の決定ではない。

2外見×2武器×11場面動作で44の対応セル。画像44枚という意味ではない。根守りの結界杖を試験に使う場合は、QA専用の解放済みfixtureで行い、序盤に未解放装備を配らない。

展開候補は4人×標準/追加2外見×11場面動作=88対応セル。取得した世界R1の武器14型との相性は2外見×14=28組。家具は1室10スロット、標準10点と追加10点。自由混用の衣装パーツは含まない。

編集元・実行用・QA・権利記録をアセットID/revision/SHAで結ぶ。依存先の欠落、非対応武器、不足動作は検査で止める。原画や中間動作をまだ生成していないので、今回は制作規格の検査のみ。

性能と保存容量

512×512 RGBA8の非圧縮画像1枚は基礎画素だけで1MiB。7動作×24枚なら1衣装168MiB、4人では672MiBになる単純例がある。mipmapやGPU複製等は別。これを実機測定値と呼ばない。

全商品を常駐させず、選択中4人と場面で必要なデータをロードする。素材の圧縮、アトラス、部品再利用、必要なclipだけの先読みを比較。選択変更前に準備し、ロード中のたびに戦闘を止めない。元の高品質原画は破壊的に縮小しない。

既存159地域台帳をそのまま維持し、新しい台帳を WEAPON_PRESENTATION / OUTFIT / HOME / FURNITURE / COMMERCE に分ける。88、28、44を159へ足して「完成数」と報告しない。

9. 購入・抽選・所有権の境界

通常の探索/戦闘とキャッシュ済み外見はオフラインで継続する。購入、鑑定券の支給/消費、購入対応抽選、所有権同期はオンラインの確定台帳で行う。最初の購入前に復元可能な本人との紐付けを作る。

券の購入完了と、券を使う抽選完了は別。購入で自動的に引かない。Apple取引の検証→一度だけ台帳付与→配信の確定→適切なfinish。抽選はquote検証→残高消費/結果/保証更新を同じ取引で保存→結果を返す→開封演出。

同じoperation IDの再送は再抽選しない。結果返却前の通信断は履歴から再表示。別端末と残高/版が競合したら未消費で同期を要求する。未同期のオフライン装備変更を、壁時計の新しい方で上書きしない。初期は一つのアクティブな変更系列と、明示的な端末引継ぎを候補にする。

購入済み・ダウンロード済み・試着中・選択中を別に持つ。ファイルが消えても所有権を消さない。権利が確認できる衣装は再取得できる。通信障害を理由に即座に標準衣装へ戻さず、最後に確認した権利を利用する設計が必要。

衣装/家具の有効権利が失効したら次の安全な場面境界で標準へ。重複する有効な取得経路があれば維持。恒常効果は次回戦闘から再算定。消費済み券の返金後、装備が強化/進化/分解された場合の完全な訂正規則は未実装であり、発売前の停止条件。 通常プレイで得た資産まで機械的に削除しない。負残高やサポート判断を含め、利用条件と顧客説明を具体化する。

10. 必須表示・販売前確認

購入前に個別排出確率、現在の保証状態、対象、価格、必要券数、有償/無償の使用内訳、購入内容と反映範囲を示す。通常確率と保証回の実効確率を混ぜない。演出スキップ、購入確認、支出確認を用意し、敗北直後の強制購入画面や時間圧力を加えない。

Appleの購入前確率表示・購入通貨の非失効、StoreKitの消耗型と恒久権利、資金決済・カード合わせ・年齢制限・返金運用を一次資料で確認する。本書の仕組みを採れば法的承認済みになるわけではない。特定の異種抽選品を揃える追加報酬は初期に採らず、レシピは具体的な入手経路で再確認する。無料入手可能という理由だけで有料取引の論点が消えるとは扱わない。

衣装/家具に能力効果を付けるなら「見た目だけ課金」とは表示しない。上限に到達済みなら有効増分0を伝える。商品プレビューの各反映場面が未完成なら、その商品を販売可能へしない。
